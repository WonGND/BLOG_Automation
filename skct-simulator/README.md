# SKCT 리허설

SK그룹 종합역량검사(SKCT)의 **심층역량검사**와 **인지역량검사**를 실제 형식으로
연습하는 웹 도구다. 빌드 도구·서버·의존성이 없는 정적 페이지이므로
`index.html`을 그대로 열면 동작한다. 홈 상단 탭으로 두 검사를 오간다.

---

# 1. 심층역량검사

## 무엇을 하는가

한 문항군에 문장 세 개가 나온다. 각 문장에 ①~⑤로 답한 뒤, 그중 나와 **가장 가까운 것**과
**가장 먼 것**을 하나씩 고른다. 실제 심층역량검사와 같은 응답 방식이다.

제출하면 두 가지가 나온다.

1. **12개 역량 프로파일** — 백분위 막대(높은 순 정렬)와 12축 레이더
2. **신뢰도 3지표** — 과장응답 위험 · 응답 일관성 · 응답 균형

심층역량검사는 점수를 올리는 시험이 아니라 걸러지지 않는 것이 목표인 검사라서,
역량 점수보다 신뢰도 지표가 먼저 읽히도록 화면을 구성했다.

## 검사 세트 5종

| 코드 | 이름 | 문항군 | 문장 | 시간 | 성격 |
|---|---|---|---|---|---|
| SET A | 실전 모의 A형 | 34 | 102 | 15분 | 12역량 전 영역 표준형 |
| SET B | 실전 모의 B형 | 34 | 102 | 15분 | A형과 문항이 전혀 겹치지 않는 재응시용 |
| SET C | 10분 속성 진단 | 18 | 54 | 8분 | 시험 직전 컨디션 점검 |
| SET D | 핵심역량 집중 (VWBE·패기) | 24 | 72 | 11분 | 자발성·성취·패기·협업·리더십·성실 |
| SET E | 압박·신뢰도 집중 | 26 | 78 | 10분 | 과장응답 문항 12개 전부 + 가장 빠듯한 시간 |

## 측정 역량

성실·책임(RESP), 주도·자발(INIT), 성취·목표지향(ACHV), 패기·끈기(GRIT),
협업·팀워크(COOP), 소통·공감(COMM), 리더십·영향력(LEAD), 도전·혁신(INNO),
분석·문제해결(ANLY), 정서안정·스트레스내성(STAB), 적응·유연성(ADPT), 규범·윤리(ETHC)

## 채점 방식

- **문항 응답** — 정채점 문항은 응답값 그대로, 역채점 문항은 `6 - 응답값`으로 환산한다.
- **가깝다/멀다 보정** — 해당 역량 평균에 문항당 ±0.55를 반영한다.
- **백분위** — 원점수를 평균 3.35 / 표준편차 0.55의 정규분포로 환산한다.
  실제 SK 규준이 아니라 연습용 시뮬레이션 규준이다.
- **과장응답 위험** — "한 번도 ~한 적이 없다" 류 문항 12개의 동의 정도.
  35 미만 양호 / 35–62 주의 / 62 초과 경고.
- **응답 일관성** — 표현만 바꾼 유사 문항 쌍(역량당 최대 2쌍)의 응답 차이.
  80 이상 양호 / 66–79 주의 / 66 미만 경고.
- **응답 균형** — ①⑤ 극단 쏠림과 ③ 중앙 쏠림에 대한 감점.
  75 이상 양호 / 55–74 주의 / 55 미만 경고.

## 결과 데이터

결과 화면에서 두 가지 형식으로 내보낼 수 있다.

- **JSON** — 역량별 원점수·환산점수·백분위, 신뢰도 지표 원값, 문항별 응답 원자료 전체
- **CSV** — 문항별 응답 표 + 역량 요약 표 + 지표 표 (UTF-8 BOM 포함, 엑셀에서 바로 열린다)

응시 기록은 브라우저 `localStorage`에만 남는다. 서버로 전송되는 데이터는 없다.
두 검사의 기록은 각각 따로 쌓인다.

## 검사 중 오류에 대한 대비

응시 도중 흔히 생기는 사고를 화면에서 막거나 복구할 수 있게 처리했다.

| 상황 | 동작 |
|---|---|
| 실수로 새로고침·탭 닫기 | 이탈 경고를 띄운다. 진행 상황은 이미 저장돼 있어 되돌아오면 이어서 응시할 수 있다 |
| 브라우저 뒤로가기 | 사이트를 벗어나지 않고 홈으로 돌아간다. 진행 상황은 저장된다 |
| 제출 버튼·Enter 연타 | 중복 제출을 막아 결과가 두 번 쌓이지 않는다 |
| 버튼에 포커스가 있을 때 Enter | 버튼이 처리하도록 넘겨, 문항군이 두 칸씩 넘어가지 않는다 |
| 세 문장을 다 답한 뒤 숫자 키 | 무시한다. 마지막 응답을 덮어쓰지 않는다 |
| 같은 문장을 가깝다/멀다에 동시 지정 | 먼저 지정된 쪽이 해제된다 |
| 사생활 보호 모드 (localStorage 차단) | 검사는 정상 진행되고, 기록을 남길 수 없다는 안내를 띄운다 |
| 샌드박스 iframe에서 열었을 때 | 브라우저 `confirm`이 막히므로 확인창을 앱 안에서 직접 그린다 |
| 저장 공간 부족 | 오래된 기록의 원자료부터 정리하고 다시 저장한다. 그래도 실패하면 알린다 |
| 문항 은행·세트 정의 변경 | 예전 세션은 이어받지 않는다 (`bankVersion` 불일치) |
| 채점 중 예외 | 응답을 유지한 채 타이머를 되살리고 다시 제출할 수 있게 한다 |
| 응답이 하나도 없는 제출 | 차트 대신 안내를 보여 준다 |
| 탭을 오래 닫아 둔 경우 | 경과 시간은 저장 시점까지만 누적되므로 타이머가 튀지 않는다 |

응답할 때 화면을 통째로 다시 그리지 않고 해당 버튼만 갱신하기 때문에,
클릭·키 입력 후에도 포커스가 유지되고 화면이 깜빡이지 않는다.

## 조작

| 키 | 동작 |
|---|---|
| `1`~`5` | 문장 응답 (A → B → C 순서로 채워진다) |
| `A` `S` `D` | 가장 가깝다 |
| `Z` `X` `C` | 가장 멀다 |
| `Enter` / `→` | 다음 문항군 (마지막이면 제출) |
| `←` | 이전 문항군 |

제한 시간이 끝나면 자동 제출되고, 남은 문항은 미응답으로 채점된다.
중간에 나가도 진행 상황이 저장되어 이어서 응시할 수 있다.

## 실행과 배포

```bash
# 그대로 열기
open index.html

# 로컬 서버
npx serve .

# 단일 파일로 빌드 → dist/index.html, dist/artifact.html
node build.mjs
```

GitHub Pages는 `.github/workflows/pages.yml`이 처리한다. `main`의 `skct-simulator/`가
바뀌면 워크플로가 돌면서 `actions/configure-pages`의 `enablement` 옵션으로 저장소의
Pages를 켜고 이 폴더를 사이트 루트로 배포한다. Settings에서 따로 만질 것은 없다.

`dist/index.html`은 CSS·JS가 모두 인라인된 단일 파일이라 어디에든 그대로 올릴 수 있다.

## 구성

```
skct-simulator/
├── index.html          진입점
├── assets/
│   ├── style.css       디자인 토큰 + 레이아웃 (라이트·다크)
│   ├── bank.js         문항 은행 204문장, 12역량, 세트 5종 정의
│   └── app.js          검사지 조립 · 응시 화면 · 채점 · 결과 · 내보내기
├── assets/
│   ├── cog-exams/
│   │   └── exam1~5.js      회차별 100문항(5영역 × 20) + 지문·표·그래프 자료
│   ├── cognitive-bank.js   회차 파일을 모아 은행·세트를 조립 (허용 유형 밖은 걸러 낸다)
│   ├── tools.js            응시 도구 — 메모장·그림판·계산기 (창은 #app 바깥에 붙는다)
│   ├── cog-guide.js        유형별 개념·치트키·예시·예상문제 13카드
│   └── cognitive.js        개념 정리 화면 · 인지역량 응시·일시정지·채점·결과
├── build.mjs           단일 파일 빌드
└── dist/               빌드 산출물
```

`app.js`가 셸(상단바·테마·토스트·라우팅·저장소)을 만들고 `window.SKCT`로 노출하면,
`cognitive.js`가 그것을 받아 `cog-*` 화면을 그린다. 두 검사가 같은 페이지·같은
디자인 토큰을 쓰면서 코드는 분리돼 있다.

타이포그래피는 표제 **Gothic A1**, 본문 **Noto Sans KR**, 수치·라벨 **IBM Plex Mono**의
세 역할로 나눴다. 본문은 16px / 행간 1.72이고, 한국어가 어절 중간에서 끊기지 않도록
`word-break: keep-all`을 적용했다.

문항군은 세트별 고정 시드(`SKCT_SETS[].seed`)로 조립하므로, 같은 세트는 몇 번을 열어도
같은 문항이 같은 순서로 나온다. 한 문항군 안에는 서로 다른 역량의 문장만 들어간다.

# 2. 인지역량검사

정답이 있는 검사다. 채점되고, **모든 문항에 해설이 붙는다.**

## 출제 유형 — SKCT 기술사무직 5영역만

응시자 안내문의 5영역과, 각 영역에서 실제로 나오는 유형만 담았다. 다른 적성검사에서
자주 보이는 어휘·어법·한자성어·중의성, 도식추리, 문자 규칙, 집합, 도형·시계각 같은
유형은 SKCT 기술사무직 구성이 아니므로 **은행에서 걷어냈다.**

| 영역 | 유형 |
|---|---|
| 언어이해 | 배열 · 빈칸 · 주제 · 제목 · 내용 일치/불일치 · 요약 · 추론 · 보기 사례 설명 · 서술방식 |
| 자료해석 | 일반 자료해석 · 표 분석 · 모두 고르시오 · 그래프 분석 |
| 창의수리 | 방정식 · 비례 · 평균 · 농도 · 일률 · 거리·속도·시간 · 확률 · 경우의 수 · 원가·할인·이익 |
| 언어추리 | 명제 · 대우 · 삼단논법 · 조건추리 · 순서추리 · 배치추리 · 진실게임 |
| 수열추리 | 수 규칙 |

**난도 개편** — 응시자 검토에서 "전반적으로 너무 쉽다"는 지적을 받아 **500문항을 모두 다시
썼다.** 형식이 아니라 난도를 올리는 개편이라, 영역마다 어려워지는 지점이 다르다.

| 영역 | 바뀐 것 |
|---|---|
| 언어이해 | **1지문 1문항**으로 바꾸고 지문 100편을 새로 썼다. 빈칸은 단어가 아니라 **문장 단위**이며, 선택지 다섯 줄이 모두 완결된 문장이라 어휘 감각으로는 갈리지 않는다 |
| 자료해석 | 자료를 키웠다. 행 7 · 열 6까지, **합계 행 50개 · 각주 29개 · 두 개짜리 표 12개**. 한 번에 끝나는 문항이 없고 두세 단계를 거친다 |
| 창의수리 | 두 개념을 겹치거나 도중에 조건이 바뀐다 — 둘이 하다 한 명이 빠지고, 물을 부은 뒤 소금을 더 넣고, 무료 구간이 붙은 요금제를 비교한다 |
| 언어추리 | 조건은 짧게 두되 **선택지를 어렵게** 했다. 정답만 모든 경우에서 참이고 나머지 넷은 "참일 수도, 아닐 수도" 있어 하나씩 따져 봐야 갈린다 |
| 수열추리 | 단순 등차·등비를 전부 걷어냈다. 계차등비 · 연산교대 · 이중수열 · 군수열 · 점화식 · 부호교대 · 소수점 · 분수 여덟 갈래로 다시 짰다 |

### 함정을 설계로 넣었다

문항을 자동으로 짜되, **눈으로 집어낼 수 있으면 채택하지 않는 조건**을 걸었다.

- 자료해석의 «증가율 1위»는 «증가액 1위»와 반드시 다른 항목이 되게 했다. 큰 수 하나만 보고 고르면 틀린다.
- «모두 고르시오»의 기준값(20%, 1.5배 …)은 실제 값 바로 옆에 둔다. 계산하지 않으면 참·거짓이 갈리지 않는다.
- 두 표를 엮는 문항은 분자 표에서 1위인 항목이 나눈 뒤에도 1위인 경우를 버렸다.
- 오답 선택지는 흔한 실수에서 뽑는다 — %와 %p를 바꿔 쓴 값, 분모를 전년으로 잡은 값, 지수와 증가율을 혼동한 값, 기차 길이를 빼먹은 값.
- 수열은 규칙 탐지기 열 종을 전수로 돌려 **빈칸 값이 둘로 갈리는 수열은 버린다.**

### 검산

500문항 전부를 **생성기와 별개의 프로그램으로 다시 풀어** 답을 맞춰 봤다. 검산기는 생성기의
중간값을 쓰지 않고, 응시자가 실제로 보는 표·그래프·발문·조건 문장만 다시 읽어 답을 구한다.

| 영역 | 검산 방식 | 결과 |
|---|---|---|
| 자료해석 100 | 렌더된 표·그래프 문자열을 파싱해 재계산 | 불일치 0 |
| 창의수리 100 | 발문의 수만 읽어 재계산 + 확률·경우의 수는 전수 열거 | 불일치 0 |
| 언어추리 100 | 조건·선택지 한국어를 구조로 되읽어 가능한 경우를 전부 펼침 | 정답 유일·일치 |
| 수열추리 100 | 독립 구현한 규칙 탐지기로 유일해 확인 | 불일치 0 |
| 언어이해 100 | 정답 자리 재배치 전후 대조(정답 문장·보기 구성·해설 기호) | 불일치 0 |

## 개념 및 치트키 정리

인지역량검사 탭을 열면 **가장 먼저 나오는 화면**이다. 5영역을 13개 유형으로 나누고
유형마다 네 가지를 붙였다.

| 블록 | 내용 |
|---|---|
| 개념 | 그 유형이 무엇을 묻는지, 어디서 틀리는지 |
| 치트키 | 더 빨리 푸는 법 — 계산을 줄이는 형식, 선택지를 지우는 기준, 단골 함정 |
| 예시 풀이 | 대표 문제 하나를 단계로 쪼갠 풀이와 답 |
| 예상문제 | 유형당 2~3문항. 선택지를 누르면 바로 채점되고 해설이 열린다 |

총 **13개 유형 · 치트키 64개 · 예상문제 28문항**이다. 카드는 글의 구조, 주제·제목·요약,
독해·추론, 수치 계산, 표·그래프 판단, 방정식·비례·평균, 농도·일률·속도, 확률·경우의 수,
원가·할인·이익, 명제·논리, 조건·순서·배치, 진실게임, 수 규칙으로 나뉜다.

카드 왼쪽 라벨은 결과 화면의 **유형군 이름과 같다.** 응시 기록이 쌓이면 카드마다 그
유형군의 내 정답률이 배지로 붙어(70% 이상 초록 / 50~69% 노랑 / 50% 미만 빨강),
채점 결과에서 약했던 유형군을 개념 카드로 바로 이어서 볼 수 있다. 13개 카드는 문항
은행의 세부 유형 **31개를 남김없이 덮는다**(언어이해 9 · 자료해석 4 · 창의수리 9 · 언어추리 8 · 수열추리 1).

### 펼치기·접기

카드 목록 위의 조작 줄은 **상단바 아래에 붙어 따라다닌다.**

- **모두 펼치기 / 모두 접기** — 13개(영역 칩이 걸려 있으면 그 영역의 카드)를 한 번에 여닫는다.
  버튼에 `7/13`처럼 지금 펼쳐진 수가 같이 뜨고, 카드를 하나씩 여닫아도 숫자와 라벨이 따라온다.
  접을 때는 화면이 본문 아래로 붕 뜨지 않도록 목록 위치로 되돌린다.
- **이 영역 펼치기 / 접기** — 영역 머리글 오른쪽. 한 영역만 통째로 여닫는다.
- **영역 칩** — 한 영역만 남겨 본다. 좁은 화면에서는 칩 줄이 가로로 스크롤되어 조작 줄이 한 줄을 유지한다.

## 영역과 세트

영역당 20문항, **실전 모의고사 5회분(회차당 100문항) + 영역별 집중 5종**, 총 **500문항**이다.
회차마다 문항 유형과 난도를 같은 비율로 깔았고, 정답 번호도 500문항 전체에서
①~⑤가 **정확히 100개씩**이다. 번호를 찍어서 얻는 이득이 없도록 맞춘 값이다.

| 코드 | 이름 | 문항 | 시간 | 성격 |
|---|---|---|---|---|
| 1회 ~ 5회 | 실전 모의고사 | 각 100 | 각 75분 | 다섯 회차의 난도·유형 구성이 같다. 어느 회차를 먼저 풀어도 된다 |
| 언어 / 자료 / 수리 / 언어추리 / 수열추리 | 영역별 집중 | 각 20 | 각 15분 | 다섯 회차에서 겹치지 않게 4문항씩 |

각 회차는 **1교시 언어이해 → 2교시 자료해석 → 3교시 창의수리 → 4교시 언어추리 → 5교시 수열추리** 순으로
영역당 20문항 15분씩 진행되며, **남은 시간은 다음 교시로 넘어가지 않는다.** 교시 사이에는 준비 화면이 들어간다.

> 영역 구성과 세부 유형은 응시 안내문 및 응시자 검토를 반영한 것이다.
> 영역당 20문항 15분은 공개된 형식을 참고한 값이므로, 문항 수와 제한 시간은
> 실제 **SKCT 응시자 안내사항**을 기준으로 확인해야 한다.

### 자료

자료 **200개** — 지문 100편(평균 343자), 표 79개(단일 67 · 두 개짜리 12), **그래프 21개**(막대 12 · 꺾은선 9).
지문도 자료도 **문항 하나가 하나씩** 쓴다. 각 회차의 자료는 그 회차 문항만 참조한다.

표는 실제 시험지 크기로 키웠다. 최대 7행 6열이고, **합계 행**이 옅은 배경으로 구분되며,
«고용률 = 취업자 ÷ 생산가능인구 × 100» 같은 **각주**가 29개 붙는다. 한 문항이 표 두 개를
엮어 나누게 하는 경우가 12개다.

그래프는 인라인으로 그리며, **모든 마크에 값을 직접 붙인다.** 자료에서 정확한 수를 읽어
계산해야 하는 시험 자료라서, 값을 가리고 마우스를 올려야 보이게 두면 문항이 성립하지
않기 때문이다. 막대는 0에서 시작하고 꺾은선도 0 기준선을 그려, 축을 잘라 기울기를
부풀리지 않는다. 계열 색은 두 칸만 쓰며 라이트·다크 각각 명도대·채도·색각 분리·대비
검사를 통과한 값이다(라이트 `#2a78d6`/`#c9541f`, 다크 `#3987e5`/`#d9713f`).

## 응시 도구 — 메모장 · 그림판 · 계산기

실제 SKCT 응시 화면에서 제공되는 세 가지를 같은 형태로 올렸다. 응시 화면 오른쪽 아래
도크에서 열고 닫으며, 창은 머리글을 잡아 원하는 자리로 옮길 수 있다.

| 도구 | 내용 |
|---|---|
| 메모장 | 조건을 옮겨 적거나 계산 과정을 남기는 고정폭 메모. 입력하면 자동 저장되어 새로 고쳐도 남는다 |
| 그림판 | 표를 그리거나 배치를 스케치하는 캔버스. 색 3가지 · 굵기 3단계 · 지우개 · 전체 지우기 |
| 계산기 | 사칙연산 · % · 부호 전환 · 한 칸 지우기. 창에 포커스가 있으면 키보드로도 두드릴 수 있다 |

- 창은 화면을 다시 그리는 단위(`#app`) **바깥**에 붙는다. 문항을 넘길 때마다 화면을 다시
  그리는데 창이 그 안에 있으면 적어 둔 메모와 그림이 그때마다 날아가기 때문이다.
- 도구 안에 포커스가 있을 때는 `1`~`5`·`P` 같은 응시 단축키가 먹지 않는다. 계산기에서
  누른 숫자가 문항 답으로 새지 않는다.
- **일시정지하면 도구도 함께 잠긴다.** 멈춰 놓고 계산기를 두드릴 수 있으면 일시정지가
  공짜 시간이 되기 때문이다.
- 좁은 화면에서는 창이 아래쪽에 붙고 한 번에 하나만 열린다.

## 시간 멈추기

응시 중 언제든 **일시정지**할 수 있다 — 상단바 버튼이나 키보드 `P`.

- 타이머가 멈추고 문제가 가려진다 (멈춰 놓고 훔쳐보는 것을 막는다)
- 멈춘 시간은 **총 소요 시간과 문항별 소요 시간 어디에도 포함되지 않는다**
- 정지 상태는 저장되므로, 새로고침하거나 나갔다 돌아와도 멈춘 지점 그대로 이어진다
- 나가기·뒤로가기·탭 닫기로 이탈해도 자동으로 정지 상태로 저장된다

**나가기**를 누르면 먼저 시간이 멈추고 확인창이 뜬다. '아니오'를 고르면 멈추기 전 상태로
그대로 돌아가고, '예'를 고르면 진행 상황을 저장한 뒤 홈으로 나간다. `Esc`는 '아니오'와
같게 동작한다. 브라우저 기본 `confirm`은 샌드박스된 iframe(아티팩트로 열었을 때 등)에서
막혀 아무 일도 일어나지 않으므로, 확인이 필요한 자리는 모두 앱 안에서 그리는 창을 쓴다.

## 문항 검수

문항을 눈으로만 보고 넘기지 않고 기계로 검증한다. 난도 개편에서는 **500문항 전부**를
문항 생성기와 별개로 짠 검산기에 다시 걸었다. 검산기는 생성기가 들고 있던 중간값을
일절 쓰지 않고, **응시자가 화면에서 보는 것만** 다시 읽는다 — 표에 찍힌 문자열, 그래프의
값, 발문의 수, 조건 문장. 생성기와 검산기가 서로 다른 답을 내면 그 문항은 틀린 것이다.

이 방식으로 잡은 것 가운데에는 **검산기 자신의 버그**도, **생성기의 버그**도 있었다. 언어추리
조건 함수가 자바스크립트 `var` 스코프 때문에 루프의 마지막 값만 붙들고 있던 문제는
검산기가 "조건을 만족하는 배열이 없다"고 되받아치면서 드러났다. 앞선 개편에서도 같은
방식으로 자료해석 40문항에서 16건(정답 인덱스 오류 11, 1·2위 동점 2, 해가 둘 1,
보기가 똑같이 먼 경우 1, 자료 자체를 고쳐야 한 경우 1)을 잡아냈다.

**계산 재검증** — 자료해석은 렌더된 표·그래프 문자열을 파싱해 비중·증감률·%p·지수·
단위당 값을 다시 구한다. 창의수리는 발문에 적힌 수만 정규식으로 뽑아 식을 다시 세우고,
확률·경우의 수는 전수 열거로 한 번 더 센다. '모두 고르시오'는 ㄱ·ㄴ·ㄷ 세 진술을 각각
계산해 조합이 정답 보기와 맞는지 본다.

**수열 유일해 검증** — 등차·등비·계차등차·계차등비·점화식·이중수열·군수열 탐지기를
생성기와 검산기가 **각각 따로 구현해** 돌린다. 빈칸 값을 하나로 결정하는 규칙이 정확히
하나뿐일 때만 채택하며, 미지수가 둘인 규칙은 관측이 셋 이상일 때만 증거로 친다
(둘로 둘을 맞추면 어떤 수열에도 들어맞아 가짜 후보가 생긴다).

**논리 퍼즐 유일해 검증** — 명제·삼단논법은 가능한 진리값 배정을, 순서·배치·조건추리는
모든 순열을, 참거짓은 (범인, 거짓말쟁이) 모든 짝을 완전탐색한다. 선택지 다섯 줄 가운데
**모든 경우에서 참인 것이 정확히 하나**이고 그것이 표시된 정답인지까지 확인한다. 나머지
넷은 "참인 경우도 거짓인 경우도 있는" 진술이라, 하나만 대충 봐서는 지울 수 없다.

**정답 자리 균형** — 500문항의 정답 번호가 ①~⑤ 각 100개가 되도록 맞춘다. 수치형 보기는
오름차순이 원칙이라 순서를 섞을 수 없으므로, 함정 선택지를 정답보다 작은 쪽과 큰 쪽에
몇 개씩 둘지로 자리를 고른다. 언어이해는 선택지를 통째로 돌리고 **해설의 ①~⑤도 같이
옮긴 뒤**, 돌리기 전후의 정답 문장·보기 구성·해설 기호가 모두 같은 것을 가리키는지 대조한다.

**구조 검사** — 선택지 5개·중복 없음, 정답 인덱스 범위, 자료 참조 유효성, 회차 간 자료
교차 참조 없음, 발문+보기+선택지 완전 중복 없음, 해설이 존재하지 않는 보기 번호를
인용하지 않는지, 그리고 **문항 은행·개념 카드·결과 화면 분류 세 곳의 유형 이름이 서로
어긋나지 않는지**까지 점검한다.

**전 구간 실행 검증** — 헤드리스 브라우저로 10개 세트를 정답키대로 끝까지 풀어 전부
만점이 나오는지, 그래프·보기 상자가 실제로 그려지는지, 320~1280px에서 가로 넘침이
없는지 확인한다.

## 고지

문항과 규준은 공개된 검사 형식을 참고해 자체 제작한 **연습용**이며 SKCT 기출이 아니다.
백분위는 시뮬레이션 규준으로 환산한 값이라 실제 응시자 집단 대비 순위가 아니다.
결과는 응답 습관을 점검하는 용도로만 쓰는 것이 맞다.
